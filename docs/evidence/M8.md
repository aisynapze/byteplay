## 2026-10-30 — HLS retention, generation isolation and combined quota gates

- **Green 5/5 GitHub-hosted CI:** [#41010209989](https://github.com/aisynapze/byteplay/actions/runs/41010209989), source commit `48ad171d47c204fc72b3046fa445ae7422345b86`. Go build/vet/unit/race/Node/CSS, seeded FFmpeg/HLS normal + race integration, responsive Chromium, real Chrome decoding and authenticated Docker smoke all completed successfully.
- Added `hls_retention.go`: a 15-minute explicit no-demand playback lifetime, minute-interval production sweeper, reclamation of inactive session registry slots, cancellation and wait before removing *only* internally owned 32-hex-ID HLS directories. Segment and explicit control actions count as demand; polling an index playlist alone does not. Reap runs on playback creation too.
- Directory layout now uses `./hls-cache/{playbackId}/g/{generation}/` for **all** generations, including generation 1, and prunes superseded subdirectories. Earlier draft stored generation 1 at the playback root and could delete its new `g/2` child; the failing real seeded integration exposed that bug. New `TestHLSGenerationPathsAreDisjoint` verifies deleting generation 1 preserves generation 2.
- `BITPLAY_CACHE_MAX_BYTES` defaults to **10737418240** (10 GiB), accepts a positive integer, and rejects malformed configuration on HLS creation. Combined usage includes both `./torrent-data` and `./hls-cache`, rather than only HLS output. Admission and generation-seek check the combined watermark; the running worker cancels on over-budget while keeping `cache_full` rather than overwriting it with `cancelled`. No active torrent files are evicted by the HLS reaper.
- Added normal/race-Go regression tests for inactive eviction, active playback preservation, unrelated file safety, combined quota accounting, configuration parsing, failure precedence, and disjoint generations. Race-enabled HLS integration verified the playlist survives successive forward/audio seeks, 410 stale generations and scoped segment serving. Observed non-race and race fixtures: 4 finalized segments and 7,864,320 of 244,451,667 torrent bytes completed by the test's final status (not a throughput/CPU claim).
- **Still OPEN:** shared quota is a conservative measured watermark, **not** atomic disk-space reservations for competing workers; storage can overshoot between checks. Persistent torrent cache has no per-file oldest-first eviction. No crash-orphan HLS cleanup across process restart has been certified. No measured long-run disk/RSS/CPU/startup contention, 30-minute MKV PTS accuracy, Firefox/Safari real decoding or production certification. M5/M8 stay partial.
